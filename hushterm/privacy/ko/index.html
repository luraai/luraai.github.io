개인정보 처리방침

시행일: 2026년 10월 31일 · English

Hushterm은 계정이 없고, 사용자의 정보를 LuraAI 서버로 보내지 않습니다. 명령어와 터미널 출력은 사용자의 기기와 사용자가 지정한 서버 사이에서만 오가며, AI는 기본적으로 기기 안에서 실행됩니다. 사용자가 직접 AI 제공자를 연결한 경우에만 데이터가 기기에서 그 제공자로 직접 전송됩니다. 분석·광고·추적 SDK는 없습니다.

1. 수집하는 정보

LuraAI(이하 "회사")는 Hushterm(이하 "앱")을 통해 개인정보를 수집하지 않습니다.

  • 회원가입과 로그인이 없습니다.
  • 이름, 이메일, 전화번호, 위치 정보를 요청하거나 수집하지 않습니다.
  • 분석, 추적, 광고 프레임워크와 제3자 SDK를 사용하지 않습니다.
  • 회사 서버로 데이터를 보내는 네트워크 코드가 없습니다.

2. 기기에 저장되는 정보

앱이 동작하는 데 필요한 아래 정보는 사용자의 기기 안에만 저장됩니다.

  • 호스트 정보(이름, 주소, 포트, 사용자 이름, 태그), 폴더, 포트 포워딩, 스니펫, 최근 명령어
  • SSH 비밀번호와 개인 키: iOS 키체인에 저장됩니다. Secure Enclave 키는 기기 밖으로 나갈 수 없고, 개인 키는 기기를 떠나지 않습니다.
  • 접속한 서버의 호스트 키 지문(첫 접속 시 확인한 값)
  • 서버 점검 결과(호스트별 최근 몇 건), AI 에이전트 요청과 사용자의 결정 기록, 직접 만든 점검, 리눅스 연습 진행 상황
  • 앱 설정(테마, 키 막대, 스크롤백, 앱 잠금 등)과 Pro 구독 상태
  • 플레이북, 운영 기록(운영 데크의 기록), 플릿 질문 결과, 로그 렌즈 결과
  • AI 제공자 설정(제공자, 주소, 모델, 제공자·주소별 동의 기록). 사용자의 AI 제공자 API 키는 기기의 키체인에만 저장되며 iCloud로 동기화되지 않습니다.

3. 서버 접속과 터미널 내용

SSH·SFTP 연결은 사용자의 기기에서 사용자가 지정한 서버로 직접 맺어지며, 회사의 중계 서버를 거치지 않습니다. 터미널에 보이는 출력과 전송하는 파일은 회사가 볼 수 없습니다. 연결된 서버에서 일어나는 일에는 그 서버 운영자의 정책이 적용됩니다.

서버 점검. 서버 점검은 사용자가 지정한 서버에서, 사용자의 SSH 연결로, 읽기 전용 명령(고정된 허용 목록 또는 같은 허용 목록을 통과한 직접 만든 점검)만 실행합니다. 결과는 기기 안에서 판정되고 기기에만 저장되며, 회사나 제3자에게 전송되지 않습니다(사용자가 4항의 AI 제공자를 직접 연결해 결과 요약을 보내는 경우는 예외). 리눅스 연습 과정은 앱 안의 가상 서버에서 실행되며 네트워크를 쓰지 않습니다.

4. AI 기능과 음성 입력

기본적으로 명령어 제안, 오류 분석, 출력 요약, 접속 진단, 로그 렌즈 설명, 플릿 질문의 답, 플레이북 설명은 Apple Intelligence의 온디바이스 모델로 기기 안에서 만들어지며, 쓸 수 없으면 기기 안의 규칙이 쓴 문장을 보여 줍니다. 앱 안의 가상 서버에서 쓰는 데모 모델은 앱에 들어 있는 고정 시나리오로 동작하고 네트워크를 쓰지 않습니다. 위험 명령 판단과 점검 판정은 모델이 아니라 기기 안의 규칙 엔진이 합니다. 음성 입력은 기기 내 음성 인식만 사용합니다.

사용자가 직접 연결하는 AI 제공자(선택, Pro). 설정 › 내장 에이전트에서 사용자가 자기 API 키로 Anthropic(Claude), OpenAI 호환 서비스, 또는 자기 서버의 모델을 연결한 경우에만, 내장 에이전트·장애 조사를 쓰거나 플릿 질문·로그 렌즈·플레이북의 설명 문장을 만들 때 다음 데이터가 사용자의 기기에서 그 제공자로 직접 전송됩니다: 사용자가 적은 목표나 질문, 서버 이름·운영체제·프로덕션 여부, 앱이 실행한 읽기 전용 명령과 사용자가 승인한 명령의 출력, 점검·로그 결과의 요약. 보내기 전에 개인 키·토큰·비밀번호 같은 비밀 값을 자동으로 가리지만 모든 비밀을 알아보지는 못합니다. 이 전송은 회사 서버를 거치지 않으며 회사는 그 내용을 볼 수 없습니다. 제공자가 받은 데이터를 처리하는 방식은 그 제공자의 약관과 개인정보 처리방침을 따릅니다. 처음 쓰기 전에 앱이 제공자와 주소, 보내는 데이터를 보여 주고 동의를 받으며(제공자·주소별로 기록), 설정에서 동의를 철회하고 키를 지울 수 있습니다. 같은 네트워크나 이 기기에서 돌아가는 서버를 연결하면 데이터가 인터넷으로 나가지 않습니다. 사용자가 제공자를 연결하지 않으면 어떤 데이터도 제3자 AI 서비스로 전송되지 않습니다.

5. iCloud 동기화 — 회사가 아닌 사용자의 저장 공간

iCloud 백업을 켜면 호스트 정보, 포트 포워딩, 스니펫, 폴더가 Apple의 iCloud 키-값 저장소를 통해 사용자의 Apple 계정에 저장됩니다. 이 데이터는 회사가 접근할 수 없습니다. SSH 비밀번호는 사용자가 "iCloud 키체인에도 비밀번호 보관"을 직접 켠 경우에만 iCloud 키체인으로 동기화되며(기본값 꺼짐), 개인 키는 동기화되지 않습니다. 설정 › iCloud에서 언제든 끌 수 있습니다.

6. AI 에이전트 승인, 위젯, Apple Watch

사용자의 SSH 세션 안에서 실행되는 Claude Code, Codex 같은 AI 코딩 에이전트가 권한을 요청하면, 앱이 터미널 텍스트에서 해당 요청을 기기 안에서 감지해 앱에 승인/거부 버튼을 보여 줍니다. Hushterm이 해당 에이전트나 제공사에 직접 접속하는 일은 없습니다. Pro에서는 앱을 떠난 직후 짧은 시간 동안 기기 안에서 로컬 알림이 표시될 수 있습니다. 승인 알림과 Live Activity는 기기 안에서 만들어지며, 푸시 서버를 쓰지 않습니다. Apple Watch에는 호스트 목록과 승인 요청이 아이폰과 워치 사이에서만 전달되며 서버를 거치지 않습니다.

7. 기기 권한

권한을 거부해도 해당 기능만 쓰지 못할 뿐 나머지는 정상 동작합니다.

권한용도
Face ID앱 잠금과 Secure Enclave 키 사용 확인. 생체 정보는 Apple이 관리하며 앱은 받지 않습니다.
마이크 · 음성 인식음성으로 명령을 말할 때만 사용하며 기기 안에서 처리합니다.
로컬 네트워크같은 네트워크의 서버에 SSH로 접속하기 위해 필요합니다.
알림에이전트 승인 요청과 연결 상태 안내(기기 안에서 예약).

8. 클립보드

붙여넣기 보호 기능은 붙여넣는 순간 기기 안에서 따옴표와 대시를 고치고 여러 줄 붙여넣기를 확인할 뿐, 클립보드 내용을 저장하거나 전송하지 않습니다.

9. 인앱 구입

월간·연간 구독과 평생 이용은 Apple의 StoreKit으로 판매됩니다. 결제와 영수증 검증은 전적으로 Apple이 처리하며 회사는 결제 정보나 Apple 계정 정보를 받지 않습니다. 구독은 Apple 계정 설정에서 해지·관리합니다.

10. 제3자 제공과 판매

회사는 개인정보를 수집하지 않으며, 사용자의 데이터를 판매하거나 제3자에게 제공하지 않습니다. 예외는 4항에 적은 대로 사용자가 직접 연결한 AI 제공자로 보내기로 선택한 데이터뿐입니다. 쿠키, 광고 식별자(IDFA), 앱 간 추적 기술을 사용하지 않습니다.

11. 암호화

앱은 표준 SSH 암호화만 사용합니다.

12. 아동

회사는 아동을 포함해 누구의 개인정보도 수집하지 않습니다.

13. 데이터 삭제

앱을 삭제하면 기기의 호스트, 설정, 키체인 항목이 삭제됩니다. iCloud에 백업한 데이터는 설정 › [사용자 이름] › iCloud › 저장 공간 관리에서 지울 수 있습니다.

14. 방침의 변경

방침이 바뀌면 위의 시행일이 함께 바뀌며, 중요한 변경은 앱 업데이트 노트로 알립니다.
